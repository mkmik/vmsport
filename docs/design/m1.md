# M1 design: a usable DCL

Decisions for M1 (see the PRD's M1). Each crate keeps the PRD split: a pure
core crate, and the host side in `libvms`.

## Devices and directories

- One physical device, `HOST:`, is the host's `/`. `HOST:[Users.mkm]` is
  `/Users/mkm`. Host names become VMS names with `vms_filespec::escape`
  per component (`.claude` is `^.claude`).
- Everything else is logical names over it, as on VMS:

  | Name | Table | Equivalence |
  | --- | --- | --- |
  | `SYS$SYSROOT` | system | `HOST:[<$VMSPORT/sys>.]`, concealed, terminal |
  | `SYS$SYSTEM` | system | `SYS$SYSROOT:[SYSEXE]` |
  | `SYS$MESSAGE` | system | `SYS$SYSROOT:[SYSMSG]` |
  | `SYS$LIBRARY` | system | `SYS$SYSROOT:[SYSLIB]` (holds `DCLTABLES.CLD`) |
  | `SYS$HELP` | system | `SYS$SYSROOT:[SYSHLP]` |
  | `SYS$LOGIN`, `SYS$SCRATCH` | job | `HOST:[Users.mkm]` (`$HOME`) |
  | `SYS$LOGIN_DEVICE` | job | `HOST:` |
  | `SYS$DISK` | process | device of the default directory |

- `dcl` starts with the default directory set to the host cwd.
- Users make their own devices with `DEFINE/TRANSLATION=CONCEALED X HOST:[a.b.]`.

## Files

- Versions are part of the host name: `REPORT.TXT;3`. A name without `;n`
  is version 1. New files get their name as the program gives it (DCL
  upcases unquoted parameters, so `CREATE x.txt` makes `X.TXT;1`).
- Lookups are case-insensitive: a directory scan.
- Directories show as `NAME.DIR;1`.
- Record attributes are in the `vms.fab` extended attribute (vms-rms
  defines the encoding). No attribute: sequential, stream_LF, CR carriage
  control.

## Images and subprocesses

DCL runs an image, a foreign command or a DCL subprocess (SPAWN, PIPE) as
a child process (fork/exec). The child finds its context on an inherited
file descriptor, `VMSPORT_CONTEXT=<fd>`, a Unix socket pair. Messages are
lines of tab-separated fields (tabs, newlines and backslashes escaped),
ending with an empty line.

DCL to child:

```
vmsport-context	1
default	HOST:[Users.mkm]
lnm	<name>	<mode>	<flags>	<equiv>...       (process table entries)
symbol	L|G	I|S	<name>	<value>              (local and global symbols)
spawn	1                                     (a DCL subprocess, not an image)
tables	<byte count>                          (then that many bytes of CLD:
                                               the verb, its syntaxes, types)
line	<command line>
```

Child to DCL, before it exits: what it changed, then its status.

```
symbol	set	L|G	I|S	<name>	<value>          (LIB$SET_SYMBOL)
symbol	del	L|G	<name>                       (LIB$DELETE_SYMBOL)
lnm	set	<logical>                            (process logical names)
lnm	del	<name>
status	%Xnnnnnnnn
```

DCL applies the changes an image sends; a subprocess's don't come back.
Without a status line DCL maps the exit code: 0 is `SS$_NORMAL`, n is
`%X1035A002 + n*8` (an error in the C run-time's facility, message already
shown). A failure the child didn't mark as shown, DCL shows.

- An image gets the command line as typed (it parses it with `tables`),
  and the parameters as argv too, for a plain Unix program named by IMAGE.
- A foreign command (`X :== $path`, or an unknown verb found through
  `DCL$PATH`) gets Unix argv as typed, and in `line` the parameters as
  LIB$GET_FOREIGN returns them (upcased and squeezed outside quotes).
- A subprocess runs `line` (empty: commands from its input, until LOGOUT),
  with stdin and stdout set up by SPAWN /INPUT and /OUTPUT or by PIPE.
- A utility run from zsh has no context fd: it builds the command line from
  its argv and parses it with its own built-in CLD.

`IMAGE SYS$SYSTEM:DIRECTORY` resolves through logical names to a host
path (also without `.EXE`, or as a Unix path); if there is no such file,
`name` lowercased is looked up in `$VMSPORT_BIN` (default `$VMSPORT/bin`,
in development the cargo target directory).

PIPE runs a lone command in DCL's own process (so `PIPE A = 1 ; B` sets
A), and pipelines as subprocesses joined by host pipes; `SYS$PIPE` and
`SYS$INPUT` are stdin. DCL reads its own input a line at a time, so what
follows stays for the images and subprocesses sharing it.

## Crates

| Crate | Pure? | What |
| --- | --- | --- |
| `vms-lnm` | yes | tables, logical names, search lists, iterative translation, SHOW LOGICAL text |
| `vmsportd` | no | the daemon (job, group, system tables) and its client |
| `vms-rms` | yes | FAB attributes, the `vms.fab` encoding, sequential record formats, carriage control |
| `vms-time` | yes | VMS times, `$ASCTIM`, `$BINTIM`, `F$CVTIME` |
| `libvms` | no | file specs to host paths, versions, `$PARSE`, `$SEARCH`, sequential files, image context, local time |
| `vms-dcl` | mostly | the interpreter; `dcl` binary |
| `vms-utils` | no | `directory`, `type`, `copy`, `delete`, `purge`, `search` |

`$VMSPORT` defaults to the source tree in development.
